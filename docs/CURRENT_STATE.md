# Текущее состояние проекта

> Статус: проверенный снимок, не roadmap. Владелец: Иван. Последняя проверка: 4 сентября 2026 года.

## Что есть в репозитории

| Область | Реализовано | Ограничение |
|---|---|---|
| Telegram | aiogram 3, `/start`, семь команд лиг | Нет кнопок, профиля, тарифов и выбора матча |
| Получение данных | StatBetting, матчи за семь календарных дат | HTML-селекторы и season ID жёстко заданы |
| Фильтрация | Только страницы со статусом `Full Time` | Отдельная модель статуса отсутствует |
| Статистика | Счёт, владение, удары, удары в створ, передачи | xG, угловые, карточки, судьи и составы отсутствуют |
| События | Голы, минуты, доступные ассисты | Парсинг зависит от позиции HTML-элементов |
| Надёжность | Timeout/HTTP/connection errors возвращают пустой результат | Нет retry, структурированных логов, мониторинга и тестов |
| Хранение | Только данные в памяти текущего запроса | Нет PostgreSQL, Redis и истории |
| Производительность | Последовательный обход дней и матчей | Синхронный `requests` блокирует event loop aiogram |

## Фактический поток

```text
Telegram command
  -> handler.py выбирает hardcoded season_id
  -> scraper.py синхронно запрашивает 7 страниц fixtures
  -> scraper.py последовательно загружает страницу каждого матча
  -> dict дополняется распарсенными значениями
  -> formatter.py создаёт HTML-текст
  -> handler.py отправляет отдельное сообщение на матч
```

## Несоответствия старому ТЗ

Архивное ТЗ указывает ESPN, шесть лиг и xG. Рабочий код использует StatBetting, поддерживает также MLS и xG не извлекает. Поэтому архив не должен использоваться как текущая спецификация.

## Основные технические риски

1. Ошибка индекса при отсутствии одной из таблиц игроков или неожиданной разметке.
2. Блокировка Telegram-обработчика на всё время HTTP-запросов.
3. Отсутствие даты, стабильного идентификатора матча и происхождения каждого поля.
4. Невозможность отличить «показатель отсутствует» от «источник сломан».
5. Непроверенные условия коммерческого использования StatBetting.
6. Отсутствие автоматической защиты от регрессии HTML-селекторов.

## Переход к продукту

Проект не переписывается целиком. Переход выполняется вертикальными срезами: нормализованная модель одного матча, асинхронный адаптер, детерминированный расчёт, хранение, Telegram-сценарий и тесты. После первого полного среза повторяемые адаптеры можно делегировать AI.
